# 八股文答案生成器

## 核心原则

1. **强制结构化** - 使用固定模板，防止发散
2. **突出对比** - 技术选型必须说明优劣
3. **关键词优先** - 必须说出专业术语（SYN/ACK、WAL、MVCC等）

## 常见八股问题参考答案

### MySQL事务ACID

```
## 一句话总结
事务保证一组操作要么全部成功，要么全部失败。

## 核心要点
1. **原子性(A)** - undolog回滚，要么全做要么全不做
2. **一致性(C)** - 数据始终符合业务约束（转账前后总额不变）
3. **隔离性(I)** - MVCC+锁，并发事务互不干扰
4. **持久性(D)** - redolog+WAL，提交后永久生效

## 对比
- 读未提交：性能最高，可能脏读
- 读已提交：Oracle默认，防脏读
- 可重复读：MySQL默认，防不可重复读
- 串行化：最安全，性能最差
```

### Redis持久化

```
## 一句话总结
Redis通过RDB快照和AOF日志两种方式保证数据不丢失。

## 核心要点
1. **RDB** - fork子进程打快照，恢复快，但可能丢数据
2. **AOF** - 记录写命令，数据更安全，但文件大、恢复慢
3. **混合持久化** - RDB+AOF结合，取长补短

## 对比
| 特性 | RDB | AOF |
|------|-----|-----|
| 恢复速度 | 快 | 慢（重放命令） |
| 数据完整性 | 差（丢分钟级） | 好（秒级） |
| 文件大小 | 小 | 大 |
| 性能影响 | 低（fork） | 高（刷盘） |
```

### TCP三次握手

```
## 一句话总结
三次握手确保双方都能收发数据，防止失效连接请求。

## 核心要点
1. **客户端 → SYN+seq=x** → 服务端（请求建立）
2. **服务端 → SYN+ACK+seq=y,ack=x+1** → 客户端（确认收到）
3. **客户端 → ACK+ack=y+1** → 服务端（双向建立）

## 为什么是三次
- 两次：服务端无法确认客户端的接收能力
- 三次：双方都能确认对方的收发能力
- 防止历史连接突然到达服务端造成混乱
```

### MVCC多版本并发控制

```
## 一句话总结
通过维护数据版本历史，实现读写不冲突。

## 核心要点
1. **版本链** - undolog串联多个版本
2. **ReadView** - 快照读，记录活跃事务ID
3. **可见性判断** - 根据事务ID判断是否可见

## 对比
| 隔离级别 | 快照时机 | 问题 |
|----------|----------|------|
| 读已提交 | 每次select创建新快照 | 不可重复读 |
| 可重复读 | 事务开始时创建一次 | 幻读（需间隙锁） |
```

### Kafka消息有序性

```
## 一句话总结
全局无序，分区（分片）内有序。

## 核心要点
1. **Topic** → 逻辑概念，多个Partition
2. **Partition** → 物理分片，内有序
3. **Key策略** - 相同key路由到同一分区

## 保证方案
- 发送时：指定partition key，相同业务进同一分片
- 消费时：单线程单分区，或保证顺序处理
- 代价：牺牲并发度
```

### 锁的类型（InnoDB）

```
## 一句话总结
记录锁锁定行，间隙锁防止幻读，临键锁两者结合。

## 核心要点
1. **记录锁(Record Lock)** - 锁定单行索引记录
2. **间隙锁(Gap Lock)** - 锁定索引间隙，防止插入
3. **临键锁(Next-key Lock)** - 记录锁+间隙锁
4. **意向锁** - 表级锁，快速判断是否可加行锁

## 对比
| 锁类型 | 作用范围 | 解决问题 |
|--------|----------|----------|
| 记录锁 | 单行 | 行冲突 |
| 间隙锁 | 索引间隙 | 幻读（插入） |
| 临键锁 | 行+间隙 | 幻读（读取+插入） |
```

### Kafka消息可靠性

```
## 一句话总结
生产者确认+Broker持久化+消费者消费，三层保障。

## 核心要点
1. **生产者** - acks=all（等所有副本确认）
2. **Broker** - 副本机制（leader+follower）、WAL持久化
3. **消费者** - 手动提交offset（消费成功再确认）

## 对比
| acks参数 | 可靠性 | 性能 |
|---------|--------|------|
| acks=0 | 最低 | 最高（发后即忘） |
| acks=1 | 中等 | 高（leader确认） |
| acks=all | 最高 | 低（所有副本） |
```

## 答题时的注意事项

1. **先说关键词** - 提到SYN/ACK、WAL、MVCC等专业术语
2. **主动对比** - 即使面试官没问，也要说优劣
3. **不要挖坑** - 不熟悉的点不要主动提
4. **控制在3-5点** - 不是越多越好，核心要点即可
