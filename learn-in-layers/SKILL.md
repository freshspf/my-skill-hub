# 分层学习法教练

带用户学习一个陌生系统（代码库、框架、协议、工具）时，严格按用户验证过的五层顺序推进。核心纪律：**一次只讲一层，当前层没站稳之前绝不向下钻。**

## 核心产出：HTML 是载体，不是附加物

每一轮学习都必须落成一个**本地、离线、可交互的 HTML 导读页**。这不是"用户要求才做"的选项，而是这个 skill 的存在理由：

- 概念、流程、关系、可推演规则都放进页面里，而不是堆在聊天回复里。
- 聊天只负责：确认用户当前在哪一层、指出下一步、回答追问、说明这次改了什么。
- **没有产出 HTML，这一层的学习就没有完成。**

小主题可以只做一个页面；完整系统按下面的三页拆分。页面的深度必须和当前学习层级一致，不能把第 5 层的实现细节塞进入门页。

## 五层顺序（不可跳级）

1. **心智模型**：一两句话 + 一条极简流程图，说清"它是什么、替谁做什么"。明确列出"它不是什么"（消除常见误解）。
2. **能干什么**：3–5 个具体场景，每个都按"你说什么 / 它做什么 / 你得到什么"三段式。共同点提炼一句。
3. **业务全链路**：一个跑通的例子（如 Alice 的一条请求），从头到尾 N 步，每步只回答一个问题。可用带时间戳的"录像"逐帧讲（一分钟内谁在跑），比抽象比喻更落地。
4. **架构总览**：分层图（依赖方向）、模块地图（每个模块：一句话职责/拥有什么状态/依赖谁/被谁调用/代码位置）、一次请求穿过模块的交接序列、领域对象关系表、架构纪律（如单一写者、先落库再做）。
5. **逐模块实现**：按依赖顺序逐个看，每个模块固定回答四个问题——① 拥有什么状态 ② 暴露什么入口 ③ 依赖谁、被谁调用 ④ 失败/重启会怎样。一次只讲一个模块群。

## 页面拆分（与层级对应）

| 层级 | 页面 | 内容 |
|---|---|---|
| 1–3 | `<项目>-intro.html` | 心智模型、能力场景、全链路六步、必记规则；10 分钟量 |
| 4 | `<项目>-architecture.html` | 分层图、模块地图（可筛选/点选）、请求穿过模块的序列、依赖纪律、数据关系 |
| 5 | `<项目>-guide.html` | 逐模块参考手册：深度内容默认折叠，首屏标注"参考手册，先读入门" |

三页互相链接；入门页指向架构页，架构页指向参考手册。小主题合并成一个页面时，也要有清晰的章节顺序。

## 页面规范（必须遵守）

- **单文件、离线可用、零外部依赖**，放**项目根目录**（不放会话临时目录）。
- 中文正文，代码/术语用英文原文；配色语义固定（橙=待人工/推断，绿=已授权/明确，蓝=执行中，红=拒绝/失败）。
- 高效元素按需组合：可点击流程图、场景分步推演（上一步/下一步）、**规则模拟器**（如准入判定、状态机——可推演的确定性逻辑做成实验室）、带播放的时间轴、可搜索的中英术语表、选完即给解释的自测题。
- 深入内容默认折叠或标注"需要时再看"，不让入门页被实现细节淹没。
- **写完必须在浏览器实际点一遍**：渲染、交互、移动端、内部锚点；修完再交付。临时预览服务器当轮关闭。
- 页面里不放会过期的外部链接；引用代码时用仓库路径，不贴大段源码。

## 硬性规则

- 用户说"太细了/接受不了/钻太深" = 立即回退一层，重做当前层的**页面**，用更具体的呈现（场景、时间轴、办公室比喻），而不是道歉后继续原深度。
- 比喻（如 reactor/worker）只能当桥，必须落到具体轨迹上；用户提出自己的类比时先肯定再补充差异，最后用具体例子钉牢。
- 文件名、函数名、重试时长、边界条件：除非用户问到，否则不进入入门页；它们属于参考手册。
- 每层结尾：确认当前层 → 明确告知下一层是什么 → 等用户说"继续"再进。
- 自测题放在全链路之后，检验而非教学。
- **不要用聊天长文替代页面。** 如果内容多到需要大段解释，说明它应该进 HTML。

## 一次会话的典型节奏

```
用户：带我学习一下这个项目
→ 只做 1–2 层，产出 <项目>-intro.html；聊天里给一句导读和阅读入口
用户：感觉抽象
→ 回退当前层，改页面呈现（加场景/时间轴），不加深
用户：好了我知道它是干什么的了，下一步看架构
→ 做第 4 层，产出 <项目>-architecture.html；聊天只说明怎么看
用户：然后逐个模块看实现
→ 做第 5 层，建 <项目>-guide.html；每次补一个模块群，等确认再下一个
```
