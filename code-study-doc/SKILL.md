# 代码研读与分层导学

用真实源码建立可靠理解，再按用户的学习方式组织内容。共用源码核验纪律，按模式决定教学节奏与主产物。

## 模式选择

| 模式 | 适用意图 | 主产物与参考 |
| --- | --- | --- |
| 深度研读（默认） | 分析一个模块、功能、原理；生成完整学习笔记 | Markdown；读取 [reference/doc-skeleton.md](reference/doc-skeleton.md) |
| 分层导学 | 带我学习、从零入门、逐层讲解；当前内容看不懂或太细 | 离线 HTML；读取 [reference/layered-learning.md](reference/layered-learning.md)，复制并改写 [assets/layered-learning.html](assets/layered-learning.html) |

从明确的用户表达选择模式，说明本轮范围即可，不要求用户再选一次。模式与对象粒度独立：SUBSYSTEM（子系统）、FEATURE（功能）、CONCEPT（概念）都可分层讲解。用户指定格式、路径或进度时优先遵从；只切换模式不重复已经完成的有效研读。

## 整项目与跨会话学习

整项目入门、多轮系列或继续上次学习时，读取 [reference/project-learning.md](reference/project-learning.md)：补齐业务定位与上下游、建立探索路线、维护产物索引和 `progress.md`。沿用该项目已有学习目录；尚未建立目录的整项目持续学习默认保存到 `~/Gitroom/项目理解/<项目名>/`。这一配套流程适用于两种模式，不增加第三种模式，也不把单次问答都升级成长期项目。

## 共同研读纪律

1. **先建立全局位置，再为本轮范围读全。** 先定位入口、模块边界和协作关系，再列必读文件清单，覆盖接口与实现、关键调用方和被调用方、模型与状态、配置、主流程和异常分支。沿调用链发现新文件就补进清单；不能只看接口、文件开头或正常路径就下实现结论。
2. **项目结论来自本次实际阅读的源码。** 引用片段标注 `仓库相对路径:行号`；运行行为还需实际运行证据，不能把静态推断当运行验证。通用知识与项目实现明确区分。类比只是理解桥梁，随后要落到具体过程。
3. **旧文档只作线索。** 用当前源码重新验证；冲突以源码为准并提示。不要自动删除、改写同主题旧文档；用户要求继续维护本次生成的导读时，可增量更新该产物。
4. **如实标注边界。** TODO、未接通、骨架、未实现、未读懂和未验证处都要说明。清单有未读文件时，不能宣称本轮已读全或交付依赖该文件的结论；先补读，或明确缩小范围后重建清单。
5. **图服务理解，且能追溯到源码。** 完整深度文档默认包含全景图和端到端流程图；当前导学层只画本层需要的图。Markdown 优先 Mermaid，HTML 用内联 SVG 或 HTML/CSS，不能依赖 CDN。图须解释含义，区分调用、依赖与共享数据关系。入门图可用职责名，但须能映射到真实模块；不要为凑图编造结构。
6. **先认知，后细节。** 先讲是什么、为什么需要，再讲实现。连续正文承载论证，图表辅助关系与比较，不把一句话拆成一个卡片。分层模式的实现细节留到相应层级。

## 共同工作流程

### 0. 识别对象、模式和本轮边界

- 从用户指定的代码、路径与问题定位对象；未指定时，先搜索结构和入口，给少量有依据的候选。仅在缺少信息会实质影响正确性时询问。
- 确定 SUBSYSTEM / FEATURE / CONCEPT；分层模式还要确定当前层和用户已掌握的内容。
- 持续学习先读取已有交接与进度，恢复当前主题、已读范围和下一步；不自动删除交接文件。
- 全项目导学先做全局扫描，再限定当前层的验证范围；不要求第一轮审计整个仓库，也不允许用局部阅读推断整体实现。

### 1. 代码勘探：清单、阅读、自证

- 建立必读文件清单并实际逐项阅读；大文件可以分段，但需覆盖本轮论点涉及的完整逻辑与分支。
- 深度模式在回复里展示清单；分层模式可将详细清单放在页面折叠的“源码依据”中，聊天只说明本轮范围。
- 写作前核对清单，声明“本轮范围为 X，必读文件 N 个，已读 N 个”；未读文件列明原因，不虚称读全。
- 下一层扩展范围时更新清单；已有事实在源码变更后重新验证。

### 2. 按模式交付

**深度研读**

- 按 `reference/doc-skeleton.md` 裁剪大纲，保留基础认知和真实实现说明；有数据模型或状态流转则说明，没有则注明不适用。
- 范围不清时先给大纲、全景图与核心理解让用户确认；用户已明确要求直接生成完整文档时直接完成。
- 展开关键文件、数据流、设计保证与故障边界；源码片段必须有路径和行号。Mermaid 使用合法节点 ID、带引号的中文标签，并验证语法；代码级细节可用 ASCII。
- 单次研读默认保存到 `docs/knowledge/NN-{主题}.md`；整项目持续学习使用已确定的统一学习目录。检查已有序号和同名文件，避免覆盖用户文档。补充 2–3 个动手实验，CONCEPT 类按需。

**分层导学**

- 按 `reference/layered-learning.md` 执行五层顺序与模板改写，主产物必须是离线 HTML，不能用聊天长文代替。
- 默认只交付当前层，结束后说明下一层，等用户继续；用户明确要求合并、跳层或一次生成完整导读时按其要求执行。
- 按本层范围核验，不把“尚未教学”写成“尚未核验”，也不把当前层已验证等同于整个项目已读全。

## 交付前检查

**两种模式共用**

- [ ] 本轮范围清楚，必读文件已实际阅读并自证，关键分支与协作关系无遗漏。
- [ ] 项目结论有源码支撑，源码片段和关键关系可追溯；通用知识、推断和未验证处已区分。
- [ ] 旧文档冲突与当前实现边界如实说明，没有无依据的保证。
- [ ] 先说明用途与心智模型，正文有连续主线，图表清晰且配解释。
- [ ] 产物保存至用户指定位置、已有学习目录或适用默认位置，没有误改无关文件。
- [ ] 整项目持续学习已更新进度与产物索引，区分代码已读、产物已完成和用户已确认理解；下一步可直接续接。

**深度研读追加**

- [ ] 关键实现、数据结构、状态流转按对象实际情况覆盖；有全景图与端到端图，Mermaid 可渲染。
- [ ] 动手实验符合用户范围，不能将未运行的实验描述成已验证。

**分层导学追加**

- [ ] 只展示当前已完成的学习内容，未制作层标记为待学习，模板示例没有冒充项目事实。
- [ ] 已按连续阅读模板生成 HTML，源码依据可展开查看，代码安全转义，零外部依赖。
- [ ] 已在浏览器检查布局、移动端、键盘与所有保留交互；无法检查的内容如实报告。
