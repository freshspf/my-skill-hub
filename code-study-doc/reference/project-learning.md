# 整项目入门与持续学习

用于陌生项目的系统学习、多轮研读或跨会话继续。它是深度研读、分层导学共用的配套流程，不是第三种模式。单个知识点的一次性解释不必创建进度文件。

## 先确认业务位置，再安排探索

读项目入口与调用关系，先回答：这个仓库承担哪个业务角色、谁调用它、依赖哪些外部服务、核心输入输出是什么。不要只从包名、技术栈或服务名推测业务定位。

建立轻量路线图，把候选主题映射到五层学习顺序：

- 心智模型、能力场景：业务定位、上下游、用户实际能完成的操作。
- 业务全链路：挑一条最有代表性的业务，从真实入口追到结果；包括同步调用、消息或任务带来的异步交接。
- 架构总览：构建模块、包职责、接口协议、对象流转、存储分工和关键约束。
- 模块实现：按业务需要深入数据访问、消息消费、定时任务、外部客户端或子业务链路。

这是探索清单，不能变成所有项目必须依次生成的八篇文档。先用全局扫描确认主题是否存在，再安排本轮清单。代码规模、方法数量只能帮助导航，不能证明业务理解。

## 识别技术栈后的勘探线索

按实际构建文件与目录结构选择线索，不把 Java 分层或某种中间件假设套到所有项目。

Java / Spring Boot 可优先查：

| 关注点 | 线索 | 需要验证什么 |
| --- | --- | --- |
| 构建与启动 | `pom.xml`、`build.gradle*`、启动类、配置档案 | 多模块依赖、真实版本、启动入口与配置来源 |
| 对外协议 | Controller、RPC 接口与实现、网关路由 | 实际暴露的路径与方法、调用方、校验与错误处理 |
| 业务分层 | application / service / manager 等实际包 | 调用方向、职责与对象转换；不能只按包名定架构 |
| 数据访问 | Mapper、Repository、实体与查询、迁移脚本 | 每种存储负责什么、事务和查询路由、缓存更新路径 |
| 异步链路 | 消息监听注解、Consumer / Listener 及注册配置 | 是否真的订阅、重试与确认语义、顺序和重复处理 |
| 定时调度 | 调度注解、Job / Task / Scheduler、配置开关 | 触发条件、并发控制、开关实际生效路径 |
| 外部依赖 | HTTP/RPC 客户端及配置绑定 | 超时、重试、降级与结果处理 |

例如先用 `rg --files -g 'pom.xml' -g '*gradle*' -g '*Controller*.java' -g '*Listener*.java'` 定位候选，再搜索实际注解、接口和调用符号。文件名筛选不是完整清单：必须继续追接口实现、注册位置和调用方。其他技术栈采用同样的业务问题，替换对应构建工具、路由、生命周期和任务入口。

## 产物位置与索引

按以下优先级确定目录，确定后在进度文件中记录，后续保持一致：

1. 用户本轮指定的位置。
2. 该项目已有的学习目录、`progress.md` 或适用的项目写作规范。已有 `~/Gitroom/项目理解/<项目名>/` 时直接续用，不另建平行知识库。
3. 尚未建立目录的整项目持续学习，默认使用 `~/Gitroom/项目理解/<项目名>/`，沿用原项目入门流程的统一存放约定。把 HTML 和 Markdown 都放在这里，不强制在仓库中创建学习目录。

单次研读没有整项目持续学习意图时，仍使用主 skill 各模式的默认路径。整项目目录规则优先于各模式的单次默认路径。写入前检查重名；不自动迁移用户已存在的文档。

Markdown 文档沿用已有编号，没有则递增编号；不要按固定主题编号预造一组空文档。HTML 按主题增量更新，索引记录当前已制作层和文件链接，无需每轮再复制一份 Markdown 正文。

## 每轮开始与结束

开始时，先读已有的 `HANDOFF.md`（如有），再读学习目录中的 `progress.md`。先恢复当前主题、已读范围、卡点和下一步，不重复从头扫描。旧结论仍需在涉及文件发生变化时重新核验；进度与交接文件都不能替代源码依据。

每轮产物落盘后更新进度，记录真实完成状态；不要只在“会话结束”时才写，避免上下文中断丢失。若没有形成新产物或结论，不机械追加空记录。代码已读、文档已生成、用户已确认理解是三种不同状态；只有用户明确确认或主动点击页面确认，才能记录“已确认理解”。页面进度与 Markdown 进度不自动跨文件同步，需要更新时明确依据。

中断时在进度中留下具体续接点、未完成阅读、待核实假设和已经排除的方向；若用户要求交接，遵从已有交接流程。不要自动调用其他 skill、删除或覆盖 `HANDOFF.md`。

## progress.md 最小骨架

使用真实状态填充以下结构，不保留示例占位当作完成记录。文件应简短，详细论证留在学习产物中。

```markdown
# 项目学习进度

## 当前定位

- 项目 / 仓库：
- 学习目录：
- 当前模式、主题、层级：
- 本轮已完成范围：
- 源码核验基线：实际可取得的提交号，或已读文件的路径与变更情况
- 用户确认理解的范围：未确认则明确写未确认

## 产物索引

| 文件链接 | 主题 / 层级 | 产物状态 | 用户确认情况 |
| --- | --- | --- | --- |

## 研读依据与关键入口

- 本轮已读文件和范围：
- 上下游、入口、核心实现、模型 / 配置路径：
- 已核实的关键结论与来源：

## 下次继续

- 下一步具体动作：
- 待读文件及原因：
- 待核实假设 / 卡点：
- 已排除的方向：
```

只记录必要的配置键名与代码位置，不把凭据或完整敏感配置写进进度。无法确认原作者设计动机时，用“从当前实现可观察到的作用”描述，不将推断写成作者明确的设计决定。
